# CS-250-Software-Development-Lifecycle

## How do I interpret user needs and implement them into a program? How do user stories help?

I interpret user needs by first understanding what the user wants the program to do and why they need that feature. User stories help by breaking those needs into smaller and easier tasks for the development team. They explain who the user is, what they want, and why they want it. This helps me stay focused on creating features that are useful to the user.

## How do I approach developing programs? What Agile processes do I hope to use?

I approach developing programs by first understanding the requirements and then breaking the work into smaller tasks. In the future, I would like to use Agile practices such as user stories, sprints, daily Scrum meetings, testing, and Sprint Reviews. These practices can help me stay organized, find problems earlier, and make changes when requirements change.

## What does it mean to be a good team member in software development?

Being a good team member in software development means communicating clearly, completing my responsibilities, and being willing to help others when needed. It is also important to listen to feedback and communicate when there is a problem. A good team works together toward the same goal instead of everyone working separately.
